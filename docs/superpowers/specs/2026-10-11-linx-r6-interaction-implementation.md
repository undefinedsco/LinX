- 日期：2026-10-11
- 依据：定稿交互稿 [`docs/design/r6-interaction-canvas/`](../../design/r6-interaction-canvas/README.md)（在线画布 Version 66）、审查报告 [`docs/reviews/linx-r6-product-audit-2026-10-10.md`](../../reviews/linx-r6-product-audit-2026-10-10.md)、[`docs/desktop-product-strategy.md`](../../desktop-product-strategy.md)

## 1. 范围

这一轮做：

- **S 全局**：rail、查找、个人卡片、编辑个人资料、退出、窄窗和中等宽度、登录、设置。
- **W 聊天与工作**：欢迎、会话、审批与输入、记住、文件消息、联系人、持续任务、收件箱、群聊、新建、编程工具。
- **K 文件与收藏**：文件夹树、表格视图、卡片弹窗、搜索、白板、引用预览、词表、收藏、共享、AI 改动草稿、授权。

这一轮不做：

- **“我的 AI”整块**（A0–A4）。rail 和窄窗“我”里的入口都去掉。做事的方法先保持现有编辑能力，从聊天信息和联系人详情里用弹窗打开。个人模型以后再说。
- **语音和视频通话**：真实通话不做。入口照常显示，点了如实提示“暂时不能打”。
- **按名字搜索加朋友**：这一轮只能粘贴账号地址。
- **改共享模型包** `@undefineds.co/models`：这一轮只用现有字段。字段不够时，把需要的改动写进开发报告，不要私自扩展。

## 2. 跨模块的产品规则（已定）

身份与聊天

- 一个身份只占一个入口：每个助手、每个人、每个群在聊天列表里只有一行。**和助手一直聊下去，不分话题（2026-10-13 修订）**：界面上没有“# 话题 ▾”、没有“新的 AI 工作”；LinX 在内部管理空间和 threads（运行、持续任务、编程工具、上下文管理），这些都出现在同一条时间线里。
- 右边栏是“聊天信息”（同微信），默认收起，点标题栏按钮打开，记住上次的开关状态；窗口窄于 1280 时浮在内容上。
- 会话只有“标星”，不设“置顶”；标星的排在前面。
- 助手当人看：联系人里助手和人在同一个 A–Z 列表里，只靠头像区分，不分页、不打标签。
- 账号显示成“名字@提供方”；复制时给完整地址。加朋友就是粘贴对方的账号地址。
- 欢迎只出现一次：第一次打开时 LinX 先打招呼，接着起名字，然后给几条开始建议。是否已欢迎过记在用户空间里，换设备也不再出现。
- 群聊：群里任何人都能叫助手；不 @ 它，需要时它也会接话（由 Reconciler 判断）。它只用这个群里的消息；要用你的卡片或文件，先私下问你。
- 持续任务没有单独入口。跟 LinX 说清要求，它回一张计划卡，确认后就是 LinX 下的一个话题。
- AI 干完活就在会话里发一条文件消息。界面不出现“成果”“草稿/保存/版本”这些说法。

决定与授权

- 等你判断的请求：只有“拒绝”和“批准这一次”，旁边可以勾“以后这类交给 LinX 判断”，勾上就是授权。这类请求永远等你，不会过期后自动通过。
- LinX 已有授权的请求：按把握留出等待时间，高把握 10 分钟、中把握 2 小时，低把握不自动通过，退回给你判断。等待期间你随时可以现在批准、拒绝，或改成“我来判断”。时间到了没人处理，就自动批准，并记下是 LinX 代你批准的。
- 花钱、删除、对外发送：没授权时每次都问你；给它们授权时要再单独确认一次。在做事的方法里关不掉这条。
- 收件箱放所有审批。LinX 代你批准的可以拿出来复查，在复查里也能收回那类授权。
- 编程工具的许可卡也是同一套规则：“允许这一次”或“以后交给 LinX 判断”。

记忆与文件

- Pod 里的东西就是你和 LinX 共同的记忆，不另建“记忆库”。平时记录对用户无感，唯一需要动手的是消息上的“记住”按钮。
- 每个助手有自己的文件夹，里面有“授权”和“记住的”两张表。
- 空间里的东西都是卡片：文件是卡片，表格里的一行也是卡片。
- 打开规则只有一条：卡片一律在大弹窗里打开（约 960 宽，最高 820），要看整页就点“展开”。左边文件树里只放文件夹和表格，不放单个文件。
- 文件夹的视图就是表格：文件当行，属性当列。看板和白板只是同一份东西的另一种视图。
- AI 改你的文件，改动先作为未确认草稿：浅紫底标出，只有“保留 / 撤销”两个选项，你接着编辑就算保留。有授权时直接保留，但仍能撤销，并记一笔可复查。
- 表格里改格子、加行直接写入，用小紫点标出、可撤销。加列没交给 LinX 时，先作为“未确认”列。删列和改列名一定问你。
- 解析只给 AI 用：用户打开文件看到的就是普通预览。AI 用到才解析，并把结果缓存起来。AI 引用某处时，点出处弹出预览，跳到那里并亮出那一段。
- 个人资料有单独的编辑页，改了立即保存到 `profile/card#me`。这份文件是公开的，所以页面上要写明“所有人可见”。电话、邮箱这一轮不做“只给朋友看”。

## 3. 协议与数据约定

### 3.1 会话协议（W2p）

- **聊天组件只接 AG-UI 事件流**（`@ag-ui/client` 1.0.2）。组件用 assistant-ui（`@assistant-ui/react` 0.15.27、`@assistant-ui/react-ag-ui` 0.0.67），依赖已装好。
- **ID 对应**：AG-UI 的 `threadId` 是内部 thread 的资源 URI（用户看不到），`runId` 是这次运行的资源 URI，`messageId` 是 Pod 里消息的 URI，interrupt 的 `id` 是 Approval 或 InputRequest 资源的 URI。
- **消息里的卡片走 A2UI v0.9**，放在 AG-UI 的 `ACTIVITY_SNAPSHOT` 里（`activityType: "a2ui-surface"`）。`surfaceId` 就是卡片绑定的 RDF 资源 URI。卡片显示什么、处于什么状态，都从 Pod 读，不读消息里留下的旧文字。资源读不到时，卡片说明原因。
- **点卡片按钮 = 写 Pod 里的那个资源。** 运行时（或 Web 端的本地运行时）盯着资源，资源变了就让那次运行接着走。所以会话里点、收件箱里点、LinX 自动通过，走的是同一条路。回答的格式能从 `shapes.ttl` 生成就从那里生成。
- **编程工具**（Codex / Claude Code / CodeBuddy）仍然用 ACP 接进运行时，由运行时转成 AG-UI 事件。界面不直接接 ACP。ACP 的 `allow_once` 对应“允许这一次”，`allow_always` 对应“以后交给 LinX 判断”（写一条授权）。
- **pi 也是运行时后面的一个后端**：走 SDK 或 RPC，不直接接到界面。
- **先在聊天里另做一版，和 ChatKit 并存。** 用一个开关切换，默认仍是 ChatKit；验收通过后，再删掉 ChatKit 和它的 CDN 脚本。

卡片目录（W2c，组件用我们自己的）：

| 卡片 | 绑定的资源 | 动作写回 |
|---|---|---|
| 审批 | Approval | 写状态和决定人；勾了“以后交给 LinX”就另写一条 Grant |
| 自动判断 | Approval + Grant | 现在批准 / 拒绝 / 我来判断 |
| 回答 | InputRequest | 写回答（排队给这次运行）；“立即插话”另发一条消息 |
| 登录 | InputRequest（类型：登录） | 外部授权，回来后把请求标为完成 |
| 文件 | 文件资源 | 打开（`useCardDialog`）、转发、收藏、移到 |
| 记住 | 记住的那一条 | 在助手文件夹的“记住的”里写一条 |
| 运行进度 | Run | 停止：写停止请求，确认真的停了才显示“已停止” |
| 未确认的改动 | 目标文件 + 草稿版本 | 保留 / 撤销（K10，第二波） |
| 命令许可 | Approval（来自编程工具） | 允许这一次 / 拒绝 / 以后交给 LinX 判断 |
| 计划 | Schedule | 确认 / 改时间 / 关掉 |
| 起名字 | Agent | 改助手的名字，身份和聊天记录不变 |

### 3.2 数据放在哪

| 东西 | 位置 | 说明 |
|---|---|---|
| 个人资料 | `profile/card#me`（`solidProfileResource`） | `vcard:fn`、`foaf:nick`、`vcard:hasPhoto`、`vcard:note`、`vcard:region`、`vcard:hasGender`、`vcard:hasEmail`、`vcard:hasTelephone` |
| 授权 | `/settings/autonomy/grants/`（`grantResource`） | 位置不变；文件树里在助手文件夹下用“授权”表来看（`GrantsView`） |
| 审批 | `/.data/approvals/`（`approvalResource`） | 自动判断的把握和到点时间只用现有字段存（例如 `assignedTo`、`decisionRole`、`leaseExpiresAt`、`context`），用法写进 `auto-judge.ts` 的注释 |
| 记住的 | `{助手文件夹}/remembered.ttl` | 每条是一个 `as:Note`：`as:content`、`dcterms:source <消息>`、`dcterms:created`、`dcterms:creator`；被替换的旧条目加 `dcterms:isReplacedBy` |
| 欢迎已完成 | `/settings/linx/welcome.ttl` | 记一个 `dcterms:date`；存在这个文件就不再欢迎 |
| AI 写的文件 | 文件 › 聊天文件 › 这个会话 | 沿用现有的 chat-files 投影 |
| 白板布局 | 视图元数据，用 JSON Canvas 格式 | 连成关系的线写成卡片之间的属性；只画线不选关系的，只留在这个视图里 |

## 4. 开发分工（并行）

每个任务在自己的 worktree 里，从同一个底座开工，**只改自己负责的目录**。需要别的模块改的地方，写进报告，不要动手改。

### T1 外壳与个人（S0、S3、S3b、S3c、S4、S5–S5d、S6、S6b、S7、S7b）

负责：`modules/{layout,profile,settings,login,my-ai}/**`、`src/router.tsx`、`src/index.css`、`src/theme/**`、`src/components/ShellStatusBadge.tsx`、`src/lib/micro-apps/**`

- **rail**：去掉“我的 AI”的入口和路由，窄窗“我”里的入口也去掉。`useOpenAgentMethod` 调用方式不变，改成打开挂在外壳上的方法编辑弹窗（复用现有 `MethodEditor`）。
- **个人卡片**：显示头像、名字、账号（名字@提供方）、空间在哪、签名，菜单是编辑个人资料、设置、切换账号、退出。出问题时卡片多一行，只给一个动作，头像右上角加标记。
- **编辑个人资料**：单独一页。每一行点了就地编辑，回车或点别处保存，Esc 放弃，立即写进 `profile/card#me`。
  - 头像上限 5 MB。
  - 分组旁标“所有人可见”，右边实时预览别人看到的你。
  - 保存中、保存失败可重试、头像太大、没网、被别的应用改过，都在页内用一行提示。
  - “在文件里打开”调用 `useCardDialog`。
- **窄窗和中等宽度**：断点是 1280 和 700。
  - 1180：右栏浮出。
  - 768：左栏 240 宽。
  - 小于 700：一次只显示一层，底栏是“聊天 / 联系人 / 文件 / 我”，收藏和设置放在“我”里，收件箱放在头部。
- **登录**：三种空间各一句人话（云端、本机、独立），其他地址收进“使用其他空间…”。每种失败只给一个主要动作，技术细节收进“详情”。
- **设置**：分组是空间与服务、通用、模型连接、本机服务、外部访问、版本更新、关于。“运行环境”改叫“本机服务”，“本地网络”改叫“外部访问”，技术词收进“高级”。通知分三项开关。

### T2 聊天列表与聊天信息（S1、S1b、S1c、S2、W6 头部和右栏、W8 群详情、W9、W10 头部和右栏）

负责：`modules/chat/**`，除了 T3、T4 负责的文件

- **列表**：一个身份一行，64px 扁平行；选中显示底色加细线；标星排前；未读、免打扰、右键菜单；还有空、加载、离线、失败、删除、无权限这些状态。
- **标题栏**：名字加“# 话题 ▾”，切换里带搜索和状态。持续任务的标题旁显示“每周一 9:00”。编程工具在跑时，标题下多一行，写清工具、文件夹、在干什么，旁边是暂停和停止。
- **聊天信息**：放助手、做事的方法（`useOpenAgentMethod`）、执行条件、查找聊天记录（包括文件、图片）、标星、免打扰、删除会话。
  - 持续任务多一组：重复、下一次、“以后自动运行”开关、最近运行。
  - 编程工具多一组：这次运行、这次允许过的命令（可撤回）、改动的文件、复制日志。
  - 群聊信息：成员（含助手）、邀请、群名称、标星、免打扰、群里的文件、助手在这个群里、退出群聊。
  - 现有的 worker 面板和会话控制条换掉。
- **“+”菜单**：找人聊天、发起群聊、新的 AI 工作，补齐 W9 剩下的状态。
- **查找**：⌘K 打开；“查看全部”跳到文件里的搜索。

### T3 会话（W0、W0b、W1、W1b、W2、W2b、W2c、W3、W3b、W4、W4b、W8 气泡、W10 卡片）

负责：`modules/chat/features/conversation/**`（新建）、`modules/chat/features/chatkit/**`、`modules/chat/services/chatkit-local/**`、`modules/chat/components/ChatContentPane.tsx`（及其测试）、`packages/agent-runtime/src/ag-ui*.ts`（新建）。在 `apps/web/package.json` 里只能加依赖。

- **新会话界面**：按 3.1 做 AG-UI 适配（覆盖 history、流式文字、思考、工具调用、interrupt），再用 assistant-ui 搭出来，放在开关后面。
- **消息**：
  - 微信式气泡，我在右、助手在左，都带头像；群消息带发言人名字。
  - AI 的过程收成一行“正在… · 第 N 步”，点开看步骤。
  - 附件像微信文件条，可以停止、可以分支。
  - 悬停时出工具条：复制、记住、收藏、⋯。
- **卡片**：做 3.1 里的卡片目录（“未确认的改动”这一轮只显示，不做保留和撤销）。动作写 Pod；倒计时用 `planAutoJudge` 的结果。
- **记住**：按 3.2 写 `remembered.ttl`，覆盖 W3b 的各种状态。
- **欢迎**：W0 / W0b，包括起名字卡和开始建议；完成后写 `welcome.ttl`。
- **文件消息**：点开调用 `useCardDialog`；引用出处带 `locator`。

### T4 联系人（W5、W5b、W5c）

负责：`modules/contacts/**`、`modules/chat/components/AddChatDialog.tsx`（及其测试）

- **列表**：人和助手在同一个 A–Z 列表里，上面是“新的朋友”和“群聊”；没有分页和标签，也没有右边栏。
- **详情**：发消息、语音通话、视频通话（后两个点了提示“暂时不能打”）。助手多两行：做事的方法（`useOpenAgentMethod`）和执行条件。
- **“TA 的空间与权限”一组**：
  - 账号地址：显示名字@提供方，复制时给完整地址。
  - 资料来自 TA 的公开资料，可以刷新。
  - TA 共享给我的、我共享给 TA 的。
  - TA 在我空间里能做什么。
  - 在我的公开资料里显示 TA。
- **删除联系人**：可以顺便收回共享。
- **加朋友**：粘贴账号地址，覆盖 W5b 的各种状态。

### T5 收件箱与授权（W7、W7b、W7c、K11、自动判断）

负责：`modules/inbox/**`、`packages/agent-runtime/src/{auto-mode,auto-judge}.ts`，以及它们在 `packages/agent-runtime/test/` 下的测试

- **收件箱列表**：只有“待处理 / 已处理”两页，每行写清要你批准、回答还是登录。
  - 下面一组“LinX 会自动通过 · N”：显示倒计时，可以现在批准、拒绝或改成我来判断，不算进待处理数。
  - “LinX 自动通过的 · N ›”进 W7c 复查：写为什么批（引用授权和方法）、做了什么，可以点“没问题”，或“以后这类都问我”（收回授权）。
  - 活动记录放在左边栏底部。
- **详情**：就是那张卡片放大，有拒绝、批准这一次，可勾“以后这类交给 LinX 判断”。给花钱、删除、对外发送授权时，再弹一次确认。
- **`GrantsView`（K11）**：列出哪类事、拿不准时怎么办、谁什么时候授权的、用过几次，每条都能收回；还要能设置三档等待时间。
- **运行时**：
  - 实现 `planAutoJudge`：按 target、action、riskCeiling 匹配授权，排除已收回的；花钱、删除、对外发送必须有单独确认过的授权。
  - 秘书原来 5–60 秒的反应窗口，换成按把握的等待时间。
  - 到点自动批准，记下代批的人和角色，留下可复查的记录。
  - Web 端在收件箱模块里跑一个定时检查，把到点的请求批掉。

### T6 文件核心（K0、K1、K1b、K2、K2b、K3、K3b、K6、K6b、K6c、K6d、K8、K8b）

负责：`modules/files/**`，除了白板相关文件（T7）

- **文件树**：搜索加文件夹树，只放文件夹和表格，分“我的空间”和“共享给我”两组。
  - “词表”文件夹下放属性、类型、命名空间三张表，对应 `/.vocab/terms.ttl`、`shapes.ttl`、`namespaces.ttl`，都用通用表格视图看。

## 5. 共同规则

- **只改自己负责的路径。** 外壳挂载、路由、全局样式归 T1。
- **依赖**：只在 `apps/web/package.json` 里加或删依赖，不提交 `yarn.lock` 的改动，合并时统一重装。优先用成熟的开源组件，不手写已有开源方案能做的东西。
- **界面文字**：用中文大白话，和画板一致。不出现 IRI、inbox、token、canonical 这类词，账号一律显示成名字@提供方。
- **测试**：
  - 在自己负责的目录里补齐或更新测试。
  - `cd apps/web && npx tsc --noEmit -p .` 要通过。
  - 改过的文件跑 eslint，不能新增错误。
  - vitest 和底座的基线对比，不能新增失败；基线是 `r6/parallel-base` 上的全量结果。
- **提交**：只在自己的 worktree 分支上提交，不推送，不改别人的分支。
- **报告**：写清做了什么、对应哪些画板、怎么验证的、没做完的、需要别的模块改的地方。

## 6. 合并与验收

1. 按 T1 → T4 → T5 → T6 → T7 → T2 → T3 的顺序，把各分支相对底座的改动合进主 worktree，然后重装依赖。
2. 全量跑 `tsc`、eslint、vitest（和基线比）。
3. 在本机测试 Pod 上逐页对照画板截图核对，包括 1440、1180、768、390 四种宽度。
4. 更新审查报告第 7 节；问过之后，把整个 R6 合成一次提交（不推送）。

## 7. 风险

- AG-UI 的 interrupt 文档没有写明是否稳定，A2UI 用的中间件还是 0.0.x 版本。所以协议适配层要薄，卡片都用我们自己的组件。
- assistant-ui 的 A2UI 支持还不能把卡片的完整数据随动作带回去（`sendDataModel` 没实现）。不过我们的动作直接写 Pod，不依赖这一点。
- 自动判断只用审批资源的现有字段，语义要写清楚，以后模型包加了正式字段再迁移。
- 底座上全量测试已有一批既有失败（见基线），验收时只看有没有新增。
