# Module Interaction Design

## 信息架构

原型采用四个稳定一级入口；`聊天文件` 作为底部菜单直达项：

| 模块 | 用户心智 | 首屏职责 |
| --- | --- | --- |
| 聊天 | 打开就能继续工作 | 默认进入 `AI Secretary` 会话 |
| 联系人 | Contact 投影：人、Agent、群组的关系面 | 查看对象是谁、能做什么 |
| 文件 | Pod 文件浏览与 resource 管理 | 按 Finder 视角浏览路径、容器、类型和权限 |
| 收藏 | 可重入的记忆索引 | 从收藏回到原会话、原文件、原上下文 |

`Inbox` 不作为一级主导航暴露，在原型里收在右上角通知入口。它是待审批、待认证、异步结果的汇总，不抢聊天主流程。

## Chat 模块

### 默认状态

- 默认选中 `AI Secretary`。
- `AI Secretary` 是默认助手，不可删除。
- 首次进入时，Secretary 发欢迎消息并请用户赐名。
- 用户可以直接发消息、丢链接、丢文件、写任务。

### 消息流

- 普通消息：用户与助手对话。
- 系统留档消息：提示“已保存到 Pod”，但不解释 RDF/Schema。
- 待审批消息：未来以 inline card 出现在消息流，同时映射到 Inbox。
- 文件/链接消息：未来点击可打开详情，收藏后出现在 Favorites。

### 运行现场

Chat 可以显示当前工作现场，但不要把它变成配置中心：

- 当前对象：AI Secretary Contact / Agent。
- 当前 Thread：本次聊天里的工作时间线。
- 当前 Workspace：要操作的工作区。
- Repository：Workspace `.meta` 的来源信息。
- Session：开始一次运行时创建，只绑定 Agent + Thread + Workspace。

### 输入区

- 默认 placeholder：`发消息给 AI Secretary，或把链接、文件、任务直接丢进来`。
- 工具按钮：附件、图片、语音、标签。
- 发送按钮只在输入区右侧，不放复杂模型配置。

## Contacts 模块

联系人不是 AI 配置页。详情页优先回答：

- 这个对象是谁。
- 和我是什么关系。
- 我可以和它做什么。

对象类型：

- 人：普通联系人。
- Agent：包括 AI Secretary 和用户创建的助手。
- 群组：多人或多 Agent 会话。

联系人详情中的 Agent 信息只做识别和回跳：

- `Contact` 是关系卡片。
- `Agent` 是可执行能力根。
- `Agent home` 是 `/agents/{agentId}/`。
- API Key、provider、model credential 不放在联系人首屏。

## 底部菜单 / 聊天文件

`聊天文件` 和微信一样不是一级模块，而是窄侧栏底部菜单里的直达二级入口。没有“聊天设置”这一层：

```text
窄侧栏底部菜单 -> 聊天文件
```

它聚焦聊天产生或引用的文件，并支持按会话筛选：

- 聊天附件。
- 链接卡片。
- Runtime 产物。
- Pod 中和当前话题相关的容器。

最小交互：

- 打开文件 URI。
- 复制 URI。
- 收藏。
- 回到来源会话。
- 进入所在 Pod 容器。

## Pod 文件

一级 `文件` 模块负责完整 Pod 浏览和 resource 管理：

- Pod 根目录。
- 完整容器树。
- Resource 详情。
- 最近文件。
- 类型、标签、权限过滤。
- 路径、大小、修改时间和 URI。
- Agent home / Workspace / Repository 都可以作为 Pod resource 被浏览。
- Repository 只展示元信息；真正进入工作的是 Workspace。

## Favorites 模块

收藏不是快照，是“重入”：

- 收藏消息 -> 回到原消息。
- 收藏文件 -> 回到文件详情；如果它来自聊天，再提供来源会话回跳。
- 收藏联系人/Agent -> 回到对象详情。
- 收藏链接 -> 回到链接上下文。
- 收藏运行结果 -> 回到消息或 Workspace，不直接打开 Session 配置。

## Settings

设置不占一级主导航。放在左下角，作为低频入口。

本轮原型只表达入口，不设计完整设置页。
