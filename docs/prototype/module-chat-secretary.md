# Module Spec: 工作 / Chat / AI Secretary

日期：2026-09-28。实施目标，尚未以本文证明产品运行能力。

权威：[产品体验 R6](../../../homepage/docs/specs/personal-ai-product-experience-r6.md) RD01、03–06、09–12 与 F01/03/05；本模块落实 [LW-01–04、07–10、12](../../../homepage/docs/reviews/product-r6-2026-09-28/linx-workflows.md)。R5 继续规定个人 AI 目标，R4 成果保存合同继续有效；旧画板的四业务入口与固定详情栏不再是实施目标。

## 目标与入口

一级入口为 **工作 / 知识 / 我的 AI**。Chat 位于“工作”，是高频沟通与推进任务的入口，不是所有阅读、编辑和评估内容的唯一容器。默认恢复上次合法工作及草稿；首次无上下文时打开工作中的 AI Secretary。旧 Chat/Thread 资源和深链保留，由壳层映射新导航，不重建数据。

用户进入就能描述目标、发消息、引用资料。Secretary 的姓名、头像可后改；改名不能成为开始工作前的步骤。联系人从新建会话、参与者详情和工作内通讯录进入；收藏状态仍在原消息上显示，全部收藏从知识视图重入。

## 首屏与信息密度

- 工作列表保留对象识别、标题、最后消息或状态、时间、未读与置顶，不要求每项都展示全部技术状态。
- 主区突出当前目标/会话、正在发生什么、需要谁决定、结果与下一动作。普通闲聊不自动创建 Issue 或变成任务仪表盘。
- 不常驻 Secretary 简介、Agent home、Thread/Workspace/Repository 技术摘要，也不为无成果状态保留空第三栏。
- 详情按选中对象打开，一次承载成果、来源、知识、方法或运行详情。长文/比较可进入主工作面，沟通上下文保持可返回。
- 代码工作存在有效工作区时才显示相关目录/仓库；普通个人工作不显示空 Repository 字段。数据空间、使用模型与外发位置在相关操作旁可查，不用全局状态墙。
- 窄窗以同层任务切面和明确返回代替缩小多栏；关闭详情保留消息位置、输入与选择。

## 默认初始化与对象边界

首次 Pod 初始化检查默认 Secretary，缺失时按既有 use-case 创建 Agent、Contact、Chat、Thread；不在 UI 直接写资源。默认 Secretary 不可删除，允许改名/换头像；欢迎语说明可开始做什么与当前记录范围，不承诺无条件保存所有材料或每次聊天都会训练。

记住的账号直接恢复，不让 provider 配置阻断工作。Agent 默认模型从共享 AI 配置池读取，不保存明文 API Key。缺配置或本机依赖时在实际受影响动作上说明，并允许继续独立成立的工作。

| 对象 | 工作中的职责 | 边界 |
|---|---|---|
| Chat / Thread | 沟通对象与具体时间线 | 不复制 Agent 规则、skills、密钥 |
| Agent | 能力与方法配置根 | 系统配置与用户覆盖分开；共享模型拥有身份 |
| Workspace / Repository | 实际执行位置及来源信息 | 不作为普通任务的强制前置配置，不在 Session 复制仓库真相 |
| Session | 一次运行的生命周期绑定 | 不成为用户首屏配置页 |
| Task / Run / RunStep | 任务定义、一次执行、执行事实 | 沿用既有权威，不从助手文字推断完成 |

## 输入、材料与实际引用

输入区支持当前能力已接通的文字、文件、链接等入口；图标存在不代表对应消费能力成立。附件、图片、语音等须明确支持与不支持状态。复杂 provider/credential 配置留在设置；个人方法和个人模型从“我的 AI”稳定重入。

1. 发送前“本次材料”列名称、类型、来源以及处理中/可用/失败；选中引用与复制文字分开。
2. 移除本次引用不删除源资源。读取失败可单独重试或排除此项继续，不重发已成功的其他材料。
3. 显示已上传、已读取、本次实际使用、已归档各自的事实；选中不等于已经被模型使用。
4. 执行后允许查看实际采用的材料、知识与方法/模型版本；记录来自明确资源和 Run 引用，不能解析助手一句话猜测。
5. 已有权限允许的调用不重复审批；处理位置和实际外发对象在相关详情可查，新用途/新权限按原授权合同处理。
6. 输入写入/运行提交结果未知时先查询原请求；重试不重复消息或已完成外部副作用。发送失败保留草稿。

“聊天文件”作为当前工作材料/成果入口与跨会话查找能力保留，按 chat/thread 来源筛选；不是新的一级导航，也不是复制数据的仓库。消费明确 richContent/file/artifact 记录，来源入口回到同一原消息。

## 纠正、知识草稿与确认

纠正首先改变当前工作。用户可以采纳、否决、修改并写理由；不要求每次反馈额外确认。

- 明确选择“仅此次 / 保留为知识草稿”。在用户已有记录/整理范围内可发现候选并批量整理，范围必须可见可改；不授权扫描任意历史。
- 候选区分用户原话与系统提炼，带来源、条件、例外和目标范围。已有相反经验时展示冲突，不静默覆盖。
- 草稿、已确认知识、运行引用、训练授权是不同事实。“批准执行”“收藏”“未回复”不构成知识确认或训练授权。
- 用户主动保存明确经验时可直接在同一决定面核对并确认，不再添加重复确认弹窗；拒绝保留不阻断这次工作。
- 从反馈打开知识对象可修订、撤回并返回原工作。知识确认失败保留草稿，不能显示已生效。
- Secretary 补充上下文保留原话与自身 maker/来源，按需展示依据，不能无痕改写成人类说过的话。

## 方法与边界

从工作或“我的 AI”打开同一方法对象。显示本次工作/助手默认方法的范围、继承来源、版本与差异；默认不把本次纠正提升为长期规则。

可修改目标、判断标准、例外与已具备能力的组合。系统 skill 保留原版，用户改动走现有覆盖/分叉。保存成功后说明后续运行生效；当前运行需由已有 steer/恢复合同决定，不能暗示立刻替换运行中的行为。冲突展示差异并保留草稿，不以最后保存者静默获胜。

auto 只决定是否继续允许范围内的推进；方法不扩大资料/网络/外发权限，一次批准不等于长期 grant，模型启用不取消审批。API Key、后端批准策略等不混入方法大表单。实际采用版本与已保存版本分别可查。

## 持续任务定义与重入

工作内提供任务视图，从“新建任务”或“将工作设为持续任务”进入同一任务定义。核对目标、触发方式/范围、执行身份、下次运行时间及运行约束；创建前显示将持续发生什么。任务详情可修改定义、暂停/恢复未来触发、查看最近 Run 和其来源工作。暂停未来调度不停止已经运行的 Run；当前运行使用当次定义，修改后的生效范围明确。

普通闲聊和纯人际聊天不要求建立 Task。时区、错过触发、重叠运行、身份失效与重复副作用由任务 owner 的合同决定，未定义不在前端猜测调度或另建任务权威。创建/修改结果未知先查原任务，不能重复提交。具体边界与验收按 R6 F05。

## 运行、等待与恢复

工作状态来自 [Task/Run](../../../xpod/docs/task-system-design.md) 和 [Worker goal control](../secretary/symphony-worker-goal-control-spec.md)。默认折叠重复工具日志，保留阶段、等待原因、最后观测时间、实际产物和可用动作。

| 场景 | 表现与动作 |
|---|---|
| 正在工作 | 显示真实阶段，不编百分比；有能力才提供中断/控制动作 |
| 等待输入/批准 | 就地说明对象、影响与所需决定；处理后继续同一个 Run，不新建相同任务 |
| 转交 worker | 用户新输入仍进入 Secretary 当前 Thread；转交有可见确认，不悄悄改变对话对象 |
| 请求停止 | 显示已请求；收到停止事实才称已停止；关闭界面只收起观察 |
| 失联/结果未知 | 保留最后观测并标时间，先恢复原运行；不把未知当失败或完成 |
| 失败 | 指明阶段；说明继续原运行、重试阶段或新一次执行及重复影响；只重试适用部分 |
| 执行结束 | 展示产物、证据、未满足项；worker 完成与任务验收分开，不凭流式结束判定通过 |

验收主体按既有控制合同决定，只有确需用户判断才增加确认。Secretary 的自主决定保留身份、依据和 on-behalf-of 事实。停止本机、停止某次 Run、暂停未来调度与远端训练取消分别处理。

## Inline 决定与 Inbox

当前工作的执行请求、输入请求、知识确认、认证具有不同控件和含义，按 [Inbox](module-inbox-approval.md) 使用同一请求投影。提交中、已处理但运行待继续、失败、过期、另端已处理均可辨。关闭卡片不等于拒绝；长期 grant 是用户主动的独立决定。

## 成果预览、修改与保存

- 只有明确 file/artifact 记录生成成果卡；纯文本准确称文本，不从 stdout 或助手措辞猜附件。
- 预览带名称、形态、草稿/已保存状态与目标空间；可以占主区，关闭不删除草稿。
- 修改要求与具体改变对应；可对照本次前后内容，不因此另建全局版本系统。
- 保存明确新建/更新/覆盖对象；目标已确定时不重复询问，存在冲突时说明影响。仅在权威持久化成功后显示已保存。
- 失败保留草稿；重复点击/重试不得产生重复成果；他端改动不静默覆盖。
- 文件入口打开原资源，来源入口回原消息；消息归档、成果保存、知识确认和训练授权不能共用一句“已学习”。

## 个人模型入口

工作中的相关建议与“我的 AI”打开同一模型/评估对象。材料准备、授权、真实候选、独立评估、启用范围与回退按 R6 F04 和 Foundry。训练未接通时就近标状态，仍可使用工作、知识和方法；禁止以模拟成功提交。当前采用版本从 Run 事实读取，不把配置已保存当作已加载。个人模型在本次未应用时说明原因与当前实际状态，可停止、进入原版本修复，或在用户获准范围内用基础模型继续；不得静默回退后声称个人模型已参与。分支按 R6 F04，不另定调度或模型兼容协议。

## 依赖与验收

依赖 R6 DEP01–05/07：来源快照、方法生效版本、保存幂等/冲突、授权与运行续接、模型治理。缺失统一 `approval-grant-design.md` 由原 owner 补齐；当前边界参见 [Capability](../secretary/capability-contract.md) 与 [Auto](../secretary/auto-symphony-contract.md)，不在本模块创建新协议。

必须覆盖：

- 首次直接工作、老用户合法重入，改名可跳过；无空常驻详情，旧 Chat 深链仍定位原对象。
- 两份材料成功一份失败可单独恢复，实际引用可查；不重复发送/执行。
- 纠正只用于本次、草稿、确认与训练授权分开；沉默/收藏/执行批准不变正例。
- 方法范围、生效版本、并发冲突与升级保留；方法不扩大权限。
- 持续任务定义/触发范围/执行身份/下次时间清楚，暂停未来触发与当前 Run 停止分开；纯人际聊天不需 Task。长任务失联、同 Run 续接、停止竞态、部分副作用、worker 完成未验收。
- 成果保存失败/重名/冲突/重复点击，文件和原消息合法回跳。
- 1440/1180/768/390 CSS px、200%文字、键盘和必要返回；产品实际持久化/运行证据另行验收，不能继承设计画板状态。
