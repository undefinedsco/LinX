# Module Spec: Profile / Settings / AI 连接

状态：R6 目标设计，2026-09-28。对应 LS-05、06、09、10、11、12、13；[联合体验 Spec](../../../homepage/docs/specs/personal-ai-product-experience-r6.md)。

## 目标与入口

账号、凭据、连接、服务和诊断是低频设置；工作方法与个人模型是“我的 AI”的日常对象。设置不是所有与 AI 有关功能的收纳箱。当前工作遇到依赖问题可就地进入相应设置，修复后回原对象。

## 个人卡片与分组

个人卡片显示名称、当前账号、空间标签和实际访问状态，提供个人资料、设置、切换账号、退出登录。账号供应商与数据空间分别表达；Local 是云端身份加本机存储，不能混同 Standalone。

头像优先使用有效用户头像；缺失时用显示名首字符，名称也缺失时用中性人物图标。与登录/切换账号列表使用同一规则，不用产品 Logo 假扮用户身份。

设置分为账号、AI 连接、服务与空间、关于。登录后不常驻供应商选择器；切换空间是重新核对授权的绑定流程，不是 Cloud/Local 开关。

## AI 连接与个人模型分工

| AI 连接：低频共享配置 | 我的 AI：个人方法与模型 |
|---|---|
| 提供方、基础模型、命名凭据、用途、兼容/成本与连接状态 | 默认方法、工作覆盖、材料、真实候选、评估、当前 release、启用范围与回退 |
| 凭据 masked、可用/暂停、激活/使用中、最近使用、429/5xx 等已知故障 | 未训练、准备、训练中、候选待评估、无改善/不启用、可发布等真实阶段 |
| 供应商只是配置分组；密钥/模型可以为同一入口下子视图 | 一个 POM 不是提示词、Wiki、RAG、供应商目录项或 Agent 联系卡 |

复用共享 AI 配置池，不额外建 provider 设置真相。界面说明“默认配置”“可服务”“客户端已加载”“本次 Run 实际采用”的差异；只知道配置不能声称生效。

没有默认模型或连接失败时，显示缺什么和可选修复动作。**不默默轮询不同提供方，也不自动改用不同数据接收方或费用条件**。若存在领域支持的 fallback，先展示范围、触发条件、数据/成本影响与可撤销选择，并在实际运行中标识采用的提供方/模型；没有相应合同不自创策略。

所选个人模型未部署、未加载或不兼容时，明确标注“未应用个人模型”，提供停止、修复，或在已有授权范围内改用明确标识的基础模型继续。继续前说明保留的方法/知识范围与缺失的个人模型，不冒充个人模型已生效；若会改变提供方、外发或费用则需相应授权。

已保存凭据默认 masked，不进入 Contact、Agent、会话内容、日志或导航参数。用户主动输入、受控显隐和一次性生成/复制遵从原凭据合同；本文不新增凭据协议。错误既保留可诊断类别，也给用户可执行动作；不能通过藏错误而显示 ready。

## 方法、auto 与权限

方法编辑位于我的 AI 或当前工作快捷入口，显示“默认”或“仅当前工作”、继承来源与覆盖差异，并有保存、放弃、恢复默认。修改目标、标准或能力使用方式不自动更改权限。

[auto 合同](../secretary/auto-symphony-contract.md)定义单一开关：是否继续可允许的推进；backend approval/grant 决定动作能否执行。一次批准、持久 grant、方法保存、个人模型启用四者独立。设置不得另造 manual/safe/container 三档自动模式或以 autoon 等同免审批。

`docs/approval-grant-design.md` 在本轮检出缺失。涉及新增授权范围、持久化或撤回行为，必须由领域负责人补齐权威合同；本文只规定边界与可见状态，不代写审批政策。

## 服务与空间

Local 服务仅在选择对应路径/明确操作时启动。设置显示当前存储绑定、可访问渠道与服务状态；隧道 token、外网域名、LAN 等高级配置按现有服务合同进入。

Xpod 负责空间资产、访问、索引、运行与部署管理；LinX 设置显示当前依赖摘要并链接修复。知识编辑和训练表单分别由 LinX 知识/我的 AI 工作面承接，设置不复制这些表单，也不复制 Xpod 完整运维面。修复保留对象、版本、目的和合法返回点；回到 LinX 后刷新事实，不自动重新训练、创建资源或重放付费调用。

## 初始化与部分就绪

已登录、Pod 可读/可写、默认助手准备、模型连接、个人模型存在是不同事实。每个失败只禁用依赖它的动作；已获准可访问的内容可继续使用，未知权限下不假定离线缓存可读。没有个人模型属于正常状态。重试初始化复用原资源身份，不重复创建默认助手或改变存储绑定。

## 退出、切换与草稿

1. 用户明确退出/切换前，若有未保存的方法、资料选择或评估编辑，提供保存、放弃、继续编辑；保存失败保留当前草稿并说明，不假称成功。
2. 草稿、选中、搜索、订阅与恢复点按身份和空间隔离。允许保留的草稿依据既有存储/权限合同保存；敏感内容不放进跨账号通用 UI 状态。
3. 真正开始退出或切换后立即遮蔽旧业务内容，停止旧身份 UI 订阅更新并清理会话/UI 引用。登出失败也不能向下个身份泄漏内容，应提供明确恢复/重试。
4. 登录新身份后重新验证绑定和权限，恢复它自己的合法上下文；返回旧身份才可恢复它允许保留的草稿。
5. 退出登录/关闭应用不等于取消训练或 Run。显示已知仍运行的任务及后续查看入口；停止需要单独动作与服务确认。禁止用“已退出”宣称任务已停止。

## 验收

- API Key、基础模型和个人模型三个概念不混合；当前运行采用版本与默认配置可区分。
- 个人模型未应用时停止/修复/获准基础模型继续三条路径准确可见，继续不伪装为个人模型采用。
- 无默认连接/429/5xx 不触发未授权轮询；已支持的 fallback 明示实际采用与影响。
- 方法保存不扩大授权；auto 开关不改 backend approval；缺失授权合同的操作列出依赖而非猜测。
- Cloud-only 不启动 Local；Local 故障不换到 Cloud；部分初始化失败可定点重试且不重复建资源。
- 方法/评估草稿在退出、切换、失败、重入时不丢失或串号；B 账号看不到 A 的引用和搜索摘要。
- 从来源/模型/Run 修复返回原对象，权限或版本变化重新核对，副作用不重复。
- 全程键盘可用，焦点返回触发入口，状态不只依靠颜色。
