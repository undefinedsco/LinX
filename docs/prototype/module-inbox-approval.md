# Module Spec: Inbox / 决定与授权

日期：2026-09-28。按 [R6](../../../homepage/docs/specs/personal-ai-product-experience-r6.md) RD04–06、09 与 F01/03/05/06 修订；落实 [LW-04、07–09、12](../../../homepage/docs/reviews/product-r6-2026-09-28/linx-workflows.md)。这是实施合同，不表示当前产品已通过运行验收。

## 目标与入口

Inbox 是跨工作待决定入口，头部稳定可达；不新增一级导航。当前工作可就地完成决定，Inbox 负责汇总、补处理和回看。真正需用户介入、将失效或失败的事项优先；完成通知与一般日志分层，正常后台执行不制造持续告警。

## 对象与类型

同一请求在工作 inline 与 Inbox 使用同一共享对象，不复制审批数据。请求类型决定控件，不能全部用“批准”表达：

| 类型 | 当前决定 | 处理后含义 |
|---|---|---|
| 执行授权 | 对具体动作一次允许/拒绝，查看对象与影响 | 只决定该请求能否执行，不代表结果正确或长期授权 |
| 待输入 | 填写当前所需值并提交，可说明无法回答 | 继续当前运行；不把输入当权限批准 |
| 待认证 | 继续既有认证/修复流程或取消 | 返回原请求核验绑定与权限，不自动重做业务动作 |
| 知识提案 | 核对原话/建议/范围，编辑、确认或保留草稿/拒绝 | 按提案合同更新知识，不授权训练 |
| 训练或模型决定 | 进入同一材料/评估/启用对象核对相应后果 | 依 Foundry 指定阶段处理，不借通用批准越过领域门槛 |
| 结果通知 | 看产物、失败影响或回到原工作 | 通知已读不等于验收任务或认可模型 |

## 列表、详情与密度

列表先显示具体问题、来源工作、等待影响和时间；点击展开一个决定面。长材料、差异或评估进入适合阅读的主工作面，保留返回；不固定使用挤压正文的三栏弹窗。对象/来源/版本与影响就近展示，技术日志按需展开。

执行卡片至少有动作、实际请求方、目标资源/范围、后果、当前决定来源与下一动作；敏感输入使用安全字段，不回显到消息或原始日志。知识/模型卡片使用相应对象字段，不把内部风险等级当作用户唯一判断依据。

## auto、一次处理与长期 grant

采用 [Capability contract](../secretary/capability-contract.md) 的 Approval/Input、Grant Coverage 和 [Auto contract](../secretary/auto-symphony-contract.md) 的分离边界：

- auto 控制输入/推进由谁驱动，不修改后端批准策略，不创建 grant。
- 一次允许/拒绝默认只解决当前请求。Secretary 只作一次建议或既有政策允许的决定，不创建 `allow_for_session` / `allow_always`。
- 长期 grant 是用户主动选择“另设授权”的独立决定，需显示行为、对象、范围、时效与可撤回方式。不能预选，也不能以改方法或启用模型代替。
- 有效 grant 在 auto 关闭时仍可能允许请求；关闭 auto 不宣称撤销权限。
- 取消本次、撤销长期授权、停止运行分别处理；其具体强制人审类别、反应窗口、过期与撤回语义以统一授权领域合同为准。

删除旧“手动/安全操作自动/当前容器自动”三档产品模式。不能因为位于某容器就自行判定安全，也不在此文件另建 ApprovalPolicy schema。

`docs/approval-grant-design.md` 当前缺失，统一反应窗口/授权期限/撤回合同由原 owner 提供（R6 DEP05）。在明确该依赖之前，不以 UI 的计时器或假提交填补协议。

## 提交、并发与运行续接

1. 打开请求读取当前权威状态，保留 request 与原 Thread/Run/资源关系。
2. 提交显示处理中；关闭面板不取消已提交决定，也不等于拒绝。
3. 结果未知先查原请求，不能重复执行或创建新请求来“重试”。
4. 成功后同步工作与 Inbox；“决定已记录”“运行待继续”“运行已继续”分阶段显示。
5. 输入/批准续接同一 Run；已记录但续接失败只恢复失败阶段。
6. 另端处理、请求过期/撤回、权限变化停止旧表单提交，解释现状，保留允许保留的草稿；不能继续使用旧批准按钮。
7. 拒绝后继续合法部分或明确等待，按任务合同处理，不删除原任务。
8. 认证返回检查实际对象/身份/权限；若改变用途、资料版本或费用，回原决定展示差异；不因连通恢复自动训练或重做副作用。

## 来源与合法返回

沿原对象→Thread/工作→资源关系定位，UI 只保存导航提示。每次跳转重新确认身份与读取权限，不把秘密/令牌/资料正文塞进 URL。来源删除、无权限、失联分别说明；撤权不得回显旧 snapshot 内容。失败仍可回到有权限的原工作摘要，恢复列表位置、筛选与编辑状态。详见 [场景恢复](../scene-restoration-solid-modeling.md)。

## 验收

- 当前工作无需跳页即可完成简单决定；长阅读/比较不塞进小卡片。
- 输入、执行批准、知识确认、训练授权、任务验收互不替代；沉默/已读不代表同意。
- auto on/off 不隐式创建/撤销长期 grant，Secretary 不代用户创建永久权限。
- 一个请求两处同步；并发处理、过期、撤回、提交失败、结果未知均可恢复且不重复副作用。
- 认证取消/完成都回原请求，等待输入回同一 Run；决定记录成功但运行失败不会显示任务完成。
- 关闭 Inbox 不处理请求；空 Inbox 低噪音。窄窗、200%文字及键盘路径保留决定正文与返回。
- 权限撤回、跨身份跳转与敏感输入不泄露旧内容；实际授权/续接由后续实现证据验证。
