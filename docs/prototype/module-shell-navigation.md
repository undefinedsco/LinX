# Module Spec: Shell / Navigation

## 目标

提供微信-like 桌面主壳：窄侧栏、少量一级入口、聊天默认主舞台。Shell 负责模块切换，不负责业务数据。

## 范围

- 左侧窄导航。
- 用户头像入口。
- 一级模块入口：聊天、联系人、文件、收藏。
- 右上角通知入口。
- 窄侧栏最底部菜单入口。
- 桌面宽屏三栏布局规则。
- 小屏降级规则。

## 不做

- 不实现具体业务页面。
- 不创建 Pod 数据。
- 不把 Inbox、Audit、Runtime 暴露为一级导航。
- 不把聊天文件暴露为一级导航。
- 不在 Shell 里放模型配置。

## 布局

```text
Desktop >= 1180
┌────┬────────────┬────────────────────┬──────────────┐
│Nav │ List Pane  │ Content Pane       │ Detail Pane  │
└────┴────────────┴────────────────────┴──────────────┘

Narrow < 1180
┌────┬────────────┬────────────────────┐
│Nav │ List Pane  │ Content Pane       │
└────┴────────────┴────────────────────┘

Mobile-like < 820
┌────┬────────────────────┐
│Nav │ Content Pane       │
└────┴────────────────────┘
```

## 状态

| 状态 | 表现 |
| --- | --- |
| 未登录 | 不显示主壳，显示登录入口 |
| 恢复中 | 保持极简 loading，不显示 provider 选择器 |
| 已登录 | 默认打开 Chat |
| Local 服务未就绪 | Chat 内显示服务状态，不让 Shell 变复杂 |

## 导航交互

- 点击一级入口切换模块。
- 当前模块图标高亮。
- 鼠标 hover 只给轻量反馈。
- 通知入口点击打开 Inbox popover/sheet。
- 通知入口固定在内容模块头部右上角，不放进左侧窄栏。
- 窄侧栏最底部菜单入口点击后展开二级菜单。
- 头像点击打开个人卡片。

## 底部菜单

底部菜单对齐微信桌面端位置：固定在窄侧栏最下面。

二级入口：

- 聊天文件。
- 通用设置。
- 服务状态。
- 关于。

`聊天文件` 在这里出现，不占一级导航。

## 数据边界

Shell 只读取：

- 当前登录状态。
- 当前用户 profile 摘要。
- 当前模块 id。
- 全局待处理数量。

Shell 不直接读写 chat/contact/file/favorite 数据。

## 验收

- `chat` 是默认模块。
- 一级导航不超过 4 个业务入口：聊天、联系人、文件、收藏。
- Inbox 不在主侧栏业务入口里。
- 聊天文件不在主侧栏业务入口里。
- 底部菜单入口固定在窄侧栏最底部。
- 主壳在 1440、1180、390 三种宽度下不挤压聊天内容。
- 退出登录后主壳消失。
