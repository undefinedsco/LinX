# LinX 桌面产品策略：工作、知识、我的 AI

状态：R6 目标设计，2026-09-28；替代旧 Chat-first 四入口与三档自动策略。依据[联合体验 Spec R6](../../homepage/docs/specs/personal-ai-product-experience-r6.md)和[结构审查](../../homepage/docs/reviews/product-r6-2026-09-28/linx-structure.md)。设计已采纳，使用频次与实际效率尚未测试。对应 LS-01–14。

## 1. 产品承诺

LinX 是长期工作与个人判断的操作面：完成今天的工作，留下有来源的经验，再用新的任务检验自己的 AI。Xpod 承载个人数据、知识、任务、模型资产和运行基础。LinX 不是给通用聊天加一个记忆开关，也不是把每条消息送去训练。

人际交流、日志、资料和工作成果自身有价值。没有个人模型、不愿训练或材料不足的用户仍能完整开始日常工作。个人模型必须是可执行产物，知识检索、提示词和规则适应是独立能力，不能用它们冒充训练。

## 2. 日常结构

| 一级入口 | 解决的问题 | 保留的原有价值 |
|---|---|---|
| 工作 | 与人/AI 沟通、发起和继续工作、处理等待、看结果 | 私聊、群组、会话列表、未读、置顶、搜索与协作对象 |
| 知识 | 找资料、核对来源、确认与修订判断 | Files 的资源浏览、文件身份、引用、权限、收藏 |
| 我的 AI | 定义方法与边界，管理个人模型并检验是否更符合自己的判断 | Agent 的长期方法、模型与评估入口；不混入凭据列表 |

采用三个任务入口，是因为旧聊天/联系人/文件/收藏缺少稳定的个人方法和模型位置；不是已证明联系人低频。工作保留固定“协作对象”，知识保留“已收藏”，旧深链重入同一资源。若验证用户找不到人和群组，应调整快捷入口，不用导航整齐牺牲交流。

启动先恢复上次合法身份/空间下的模块、对象与阅读/编辑位置。首次无上下文进入工作；普通人际消息不要求 Task、Issue 或工作容器。默认秘书是可用入口，不是每次启动必须重开的首页。

## 3. 对话表达意图，适当的工作面承载决定

Chat-first 的可保留含义是低摩擦表达与熟悉的沟通结构，不是把资料、评估、审批和所有设置塞进消息流。

- 对话中看见目标、当前阶段、依据、等待谁决定和结果；重复工具日志默认收起，异常和批准后果不能隐藏。
- 长成果、来源精读、修订比较、材料选择与模型评估可占主区；完成后返回同一会话与位置。
- 按需打开工作列表和详情。宽窗不默认四栏，窄窗不缩小所有列；以页型和内容预算决定展开。
- 当前工作里的方法/模型入口与我的 AI 打开同一资源，不复制表单或状态。
- Inbox 处理真正需要关注的事项，Audit 保留证据；正常步骤不堆满未读提醒。

## 4. 从工作到个人判断

以独立书店为例：团队两人、没有长期维护人员，报名工具选择现成表单而非定制平台。应留下的判断是“当前不为一次活动增加长期维护负担”，同时记录条件与必要约束下的例外；不能学习成“永远不开发”。下次志愿者排班是检验泛化的新任务。

流程必须区分以下决定：

1. 纠正当前工作，可以仅用于此次；拒绝长期保留不影响完成工作。
2. 在获准整理范围内形成知识草稿；用户核对来源、适用条件和例外后确认。保存记录与确认知识不同。
3. 明确选择训练用途、材料与版本；收藏、沉默、赞或所有历史聊天都不构成授权。
4. 真实训练产生候选产物；使用相同基础模型、获准知识/规则/工具条件，在保留新任务上比较，候选额外使用个人模型产物。
5. 允许基线更好或没有改善。候选不自动启用；依 Foundry 发布结论及用户选择范围启用，实际 Run 使用另有事实。

训练协议未交付时可提供材料准备和状态阅读，但不显示模拟成功。回退影响后续任务，不改历史 Run；撤材料不能声称旧权重已经遗忘。

## 5. 方法、自动推进和授权

方法描述目标、判断标准、能力使用方式与自主范围；显示默认来源、当前工作覆盖及差异，保存/放弃/恢复默认可达。修改方法不自动扩大可读资料、外发、工具或训练用途。

采用[auto 与 Symphony 合同](secretary/auto-symphony-contract.md)：

| 概念 | 负责 | 不代表 |
|---|---|---|
| auto 单一开关 | 是否由 Secretary 继续可允许的输入/推进；关闭时由用户驱动 | 不是 manual/safe/container 三档，不改变 backend 审批配置 |
| capability / grant / backend approval | 动作是否获准及准确范围，沿用领域合同 | 不是模型偏好、工作方法或一次开关 |
| Symphony | 当前会话对接与委派边界 | 不是第三个自动等级；普通消息不自动成为 Issue |
| 个人模型启用 | 在选定范围采用指定可发布 release | 不授予工具、外发或资料权限 |

auto 事件不能伪装成用户说过的话；Secretary 代行和用户事实有可追溯来源。遇到阻塞沿现有合同处理，不把所有 tool call 都变审批，也不把 autoon 改成 never approval。worker 仍受明确能力范围约束，不因为委派获得治理/发布权。

本轮检出缺少 `docs/approval-grant-design.md`。新增 grant、撤回与批准持久化行为是实施依赖，由领域负责人补齐；本文不另造政策。现有共享合同已经定义的合法日常操作不因此全部停止。

## 6. 连接、初始化与恢复

AI 连接是低频的提供方、基础模型和命名密钥配置；个人方法和个人模型在我的 AI。缺默认配置时提示修复，不悄悄轮询提供方；fallback 只有在既有合同支持、影响与选择明确时才可使用，实际调用来源可查。

初始化分别显示身份有效、选定空间绑定、可读/可写、默认助手、模型连接、个人模型状态。没有个人模型是正常状态；助手或连接失败不让已经可读的资料消失。未知权限不开放旧账号缓存。重试复用原资源，不自动换 Cloud、创建新空间或重复初始化助手。

登录遵从[紧凑登录合同](login-modal-local-binding-spec.md)：记住的绑定直接继续；undefineds 首次选择云端/本机；本机空间保留 Cloud 身份，Standalone 是独立高级路径。保存地与身份分清，不称“同步”除非确有同步服务。

恢复区分删除、撤权、暂不可达和来源修订。跨 Xpod 修复保留原对象、版本、目的与合法返回；返回后重读事实。结果未知先查询原操作，不盲目重复付费调用、创建或训练。

切换账号前处理未保存草稿；操作开始后遮蔽旧资料，停止旧订阅，恢复新身份自己的上下文。退出登录、关闭页面、请求停止、确认停止和暂停未来调度分别表达；任务不因 UI 消失被宣称停止。

## 7. 视觉与操作密度

沿用已选 LinX 标记、纸色与墨紫。资料来源、判断理由、修订和用户控制形成气质，不靠拟人头像、人格分数、发光球或运行监控卡墙。

列表紧凑，正文和对照可读；同一处一个主要决定。设置/诊断可达但不常驻。一级导航可读，选中不只靠颜色；键盘、焦点返回、状态播报、200% 文字和窄窗必须参与验收。具体尺寸依 LinX [样式规范](ui-style-guide.md)，不直接搬 Xpod 或主站比例。

## 8. 领域权威与发布顺序

- 共享资源、身份、来源/修订遵从 models；不为工作/知识导航新造一套存储模型。
- Task 定义、Run 实例和 RunStep 事实沿原任务合同；工作列表是投影，不是第二份任务状态。
- 个人训练/评估/发布由 Personal Model Foundry 治理；LinX 是日常操作入口，Xpod 是资产和运行基础，不复制知识编辑器与训练表单。
- 权限/外发、领域状态、结果查询和幂等性先有合同，再开放真实操作。不能只写“后端待接”。

先推进已有合同范围内的导航、工作、知识和修复交接，同时保留我的 AI 稳定入口。训练真实提交依赖材料用途、Foundry 和运行采用版本合同；能力未支持时解释状态，不能假成功或删除产品主张。

## 9. 设计与实现验收

1. 旧私聊/群组/联系人/收藏深链迁入后对象不变；纯聊天不要求 Task。
2. 首次未训练可工作；返回用户恢复任一合法模块；人/群组仍好找。
3. 工作→来源/成果/比较→工作不丢上下文；1440/1180/768/390 px 与 200% 文字无空常驻列、主动作不可达或密集气泡长表。
4. 收藏、知识确认、训练选择独立；条件/来源/纠正可找回。
5. 方法与 auto 不扩大权限；provider fallback 不隐瞒外发和费用。
6. 候选有真实产物、相同知识基线和新任务评估；无改善可保留现用，启用与 Run 实际采用可区分。
7. 部分就绪、撤权、断网、身份切换、草稿未保存、结果未知各有准确恢复路径。
8. 用找人、群消息、新 AI 工作、找否决依据、当前模型、待确认六个任务对比旧/新结构，记录成功、步骤、误入和恢复情况；未验证前不宣称效率提升。

本轮只证明文档合同对齐。实际数据、调用、布局、辅助技术和恢复证据由对应开发包交付。
