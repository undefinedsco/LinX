§0 设计基准：问题如何映射到产品原则

DESIGN.md 定义的核心承诺是 Precise, calm, trustworthy —— 信任来自"状态在使用点显式可见"。本次发现的问题绝大多数可归入对以下五条产品承诺的违背：

产品承诺（DESIGN.md 原文）本次对应的典型违背
Principle 4 · State must be legible
状态显式、就地可见		AI 错误伪装成助手消息（H2）；保存失败徽标在失败瞬间消失（H1）；复制操作全线无反馈（S1）；失败静默 console.error（S2）
Never silently fall back from Local to Cloud
存储空间诚实		Web 端选"本机空间"静默回退云端（H3）
AI work state visible, interruptible, traceable
AI 工作状态可见、可中断、可追溯		停止会话无确认无反馈（H2 关联）；暂停/恢复/停止失败静默；错误分类（auth/timeout/no-content）未呈现
Keyboard reachable · WCAG 2.1 AA
全部控件键盘可达、焦点环克制可见		列表方向键选中/焦点分裂（H9）；弹层无焦点管理（H8）；div onClick 四处（S4）；hover-only 操作（S3）
Transparent waiting/error over silent cleanliness
宁要透明的等待/错误，不要安静的假象		toast 系统调试值致反馈机制失效（H11）；死控件伪装可用（S9）；破坏性操作无确认（S6）

📍 modules/files/ui/RichTextFileEditor.tsx:462-470 + features/editor/useFileEditorSheetController.ts:213-238

§2 系统性模式 12 类 · 跨模块

这些问题在全应用同构重复出现，单点修复收益小，按模式批量治理收益最大。每类附代表性样例。

模式S1

复制操作全线无反馈（8+ 处同构）

原则 4 · 状态可读files × 4 · structured × 2 · chat · profile

根源：modules/files/app/platform-actions.ts:6-9 的 copyFilesText 用 ?? Promise.resolve() 静默吞掉无剪贴板权限的场景。涉及：复制 URI（详情/列表/文件夹/subject 导航 4 处）、复制 predicate URI、复制 URL、chat 顶部"复制日志"（右键菜单版却有 toast，行为不一致）、profile 复制 WebID（复制完整 URL 但显示短 ID，所见非所得）。

现状：点了没反应（也许根本没复制上）
成功无提示；无权限时静默失败，用户贴出来的是旧剪贴板内容

模块内删除/重命名/上传均有 toast，唯独复制没有——体验断裂。

建议：统一成功/失败反馈（点击体验）
成功 toast 简短克制；失败给原因（"无剪贴板权限，请手动复制"）

copyFilesText 统一返回结果 + 全局 toast。遵循 Success 契约："Confirm what changed… do not celebrate routine actions."

模式S2

失败静默 catch → 仅 console.error（10+ 处）

异步操作失败后用户零感知：chat 标星/静音/标记未读/删除会话（ChatListPane.tsx:749-802）、暂停/恢复/停止会话（ChatContentPane.tsx:318-334）、ChatKit 顶层 onError（:560-562）、系统提示词"保存"假成功（ChatRightSidebar.tsx:57-65，无 agent 时 console.warn 后照常关闭对话框）、取消收藏 unhandled rejection（FavoriteContentPane.tsx:203-207）、files 收藏切换（两处）、contacts toggleStar fire-and-forget。建议：统一 mutation onError → toast（错误分类命名），调用点不再裸 void；乐观更新必须配回滚。
