## Root causes

1. The checked-in Web source consumes rich-content symbols not present in the pinned and installed models package version 0.2.45. This prevents a clean latest-source Vite session and build.
2. The active Chrome session mixes `127.0.0.1:5173` for LinX with Pod resources created for a `localhost:5737` identity/session. The resulting authorization failures occur before message rendering.

## Required follow-up

1. Publish and pin a models package that contains the rich-content contracts used by `message-blocks.ts`.
2. Choose one local hostname (`localhost` or `127.0.0.1`) for LinX, OIDC redirect URIs, WebID and Pod resources.
3. Clear the stale browser session, log in again through that canonical hostname, then rerun create Chat → send → stream → refresh.
