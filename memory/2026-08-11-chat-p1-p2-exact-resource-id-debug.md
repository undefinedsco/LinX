# DEBUG REPORT — Chat P1/P2 exact Pod resource IDs

- **Symptom:** P1/P2 Web and local Xpod tests passed, but expanding validation to Models and CLI produced AI credential update failures, source-entry TypeScript compilation failures, and stale tests that expected short IDs such as `jina-default`.
- **Root cause:** drizzle-solid 0.3.20 treats `findById` / `updateById` / `deleteById` values as exact base-relative resource IDs. AI config code still mixed logical short keys with storage IDs, so writes, RDF references, and later updates could target different resources. Separately, TypeScript 7 rejects single-file compiler invocations that implicitly load the repository config, while the CLI smoke tests were invoking both forms together.
- **Fix:** Models now builds canonical provider, credential, and model resource IDs, keeps logical credential IDs separate from mutation IDs, reads canonical provider IDs before legacy fallbacks, and derives settings filenames from the stable row key. CLI provider lookup and credential tests use the same contract; single-file entry compilation passes `--ignoreConfig` and the temporary bundle acknowledges TypeScript 6 deprecations.
- **Evidence:** Models full suite 29 files / 170 tests passed, including local Xpod integration; CLI 492 tests completed with 489 passed, 3 optional live tests skipped, and 0 failures; Web 375 files / 2875 tests passed; Web local-Xpod integration 16 files / 29 tests passed; Service 16/16 passed; Web production `build:check`, Chat Oxlint, release tarball export checks, and diff checks passed.
- **Regression test:** `packages/models/tests/ai-config.test.ts` verifies canonical resource construction and that `markCredentialUsed` updates `credentials.ttl#…`; `apps/cli/test/web-fetch.test.mjs`, `apps/cli/test/auth-cli.test.mjs`, and `apps/cli/test/ai-connect-boundary-smoke.test.mjs` verify consumer behavior.
- **Related:** The repository currently selects TypeScript 7 while `@typescript-eslint/typescript-estree` 8.61 declares TypeScript `<6.1` and crashes before linting. Chat-scoped Oxlint is the working lint gate; this is an existing toolchain boundary, not a P1/P2 runtime failure.
